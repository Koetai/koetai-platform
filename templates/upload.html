Upload RDF Data

Supported: .ttl .nt .n3 .rdf .owl .trig .nq .jsonld, and those compressed as .gz .bz2 .zip .tgz — max {{ max_upload_mb }} MB. Files are appended to the dataset's named graph; existing triples are not removed.

The limit is on the uploaded bytes, so compressing first is usually the way to bring a large graph in — a gzip is typically a tenth of the size. For something larger still, the Web tab fetches straight from a URL and has no such limit.

OWL RL on large files can take hours. The job runs in the background — you can close this tab and check back. {% if jena_available %}Consider RDFS for faster results. {% else %}RDFS would be faster, but needs Apache Jena, which is not installed here.{% endif %}

Fast load hands the file to the triplestore's own loader instead of sending it over HTTP — roughly seventeen times quicker on a large file. The store is stopped while it runs, so every dataset on this server is offline until it finishes, and the data is appended rather than replacing what is there. Reads .nt, .nq and .ttl, optionally .gz or .bz2.
Optimise afterwards compacts the store while it is already stopped — the loader writes a layout that is quick to write and slower to read, and recommends this when it finishes. It lengthens the outage considerably — about seven minutes on a store holding a hundred million triples, against seconds for the load itself — so it is off by default. Doing it here at least spends one outage rather than two.
